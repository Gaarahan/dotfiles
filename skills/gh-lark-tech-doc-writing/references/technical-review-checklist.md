# 技术方案 Review 清单

本清单检查方案是否成立。写入前执行一次，写入后基于最终文档再执行一次。发现阻断项时先修正，
不要把问题留给 reviewer 发现，也不要在正文记录 Review 过程。

## 一、阻断规则

出现任一情况，不得交付：

- 新对象、模块、配置或字段没有明确消费者。
- 新建机制可以被现有链路直接承载，却没有说明新增必要性。
- 同一事实同时保存在提示词、配置、清单、数据库等多个位置。
- 信息放错层：上游感知了只属于下游的细节，或下游承担了应在上游收敛的原因判断。
- 写了“Agent / 模块按需读取”，却没有说明它如何发现资源、何时读取、从哪里读取。
- 关键结论仍是猜测、待确认或与代码 / 上游契约矛盾。
- 正常、异常、取消、超时、重试、灰度关闭等关键分支没有明确行为。
- 摘要、架构、配置、时序、伪代码和任务拆分对同一职责描述不一致。

## 二、对象与范围审计

对每个新增对象、模块、配置项和协议字段，在内部回答：

| 问题 | 通过标准 |
|---|---|
| 谁拥有它？ | 只有一个明确负责人和生命周期。 |
| 谁消费它？ | 能指出具体模块、Agent、Tool 或接口。 |
| 何时消费？ | 能放进端到端时序的确定位置。 |
| 事实源在哪里？ | 只有一个权威来源，其他位置只保存引用或运行快照。 |
| 现有机制能否承载？ | 已查现有代码或配置；能复用就不新造概念。 |
| 为什么必须新增？ | 删除它会造成可说明的能力缺口。 |
| 是否属于本方案？ | 与目标无关的展示、治理、评测等内容移出正文或仅记录外部依赖。 |

特别检查所有 `Registry`、`Manager`、`Pack`、`Profile`、`Context`、`Task`、版本字段和映射表；
这些名称容易制造“看起来完整、实际无人消费”的设计。

## 三、运行时感知与分层

- 明确最终执行者：主 Agent、工具处理器、专用 Agent、子 Agent 或普通服务。
- 明确上下文注入层：系统提示、开发者上下文、工具入参、运行时插值或文件读取。
- 对每段信息执行“最小知情”检查：执行者不需要的信息不向其暴露。
- 版本、sha、灰度和回滚信息默认属于运行时与可观测性；只有影响生成逻辑时才进入模型上下文。
- 文件存在不等于 Agent 可发现。为可选能力提供常驻的轻量名称、描述和入口，再按需加载完整内容。
- “读取清单 / 配置 / 源码”必须有触发条件、确定路径和失败行为。

## 四、契约与数据闭环

- 核心接口给出请求、响应、事件或伪代码，标出新增字段、已有字段和各自消费者。
- 区分使用场景、具体枚举值、配置值和运行状态，不用场景名冒充真实模型 / 状态 / 错误码。
- 数据链路从生产者追到最终消费者，检查聚合、去重、顺序、幂等、缓存和缺失值。
- 原因只在最了解原因的一层判断；跨层优先传递下游真正需要的结论。
- 缺失关键数据不能只写注释或静默兜底；给出错误、日志、指标或明确的降级行为。

## 五、路径与边界

- 用决策表覆盖成功、系统错误、规则拒绝、用户取消、超时、重试和部分成功。
- 检查首次执行、二次修改、恢复历史版本和灰度切换是否使用一致的绑定与事实源。
- 检查开关关闭、配置缺失、依赖加载失败、版本不兼容时的行为。
- 若结果涉及权限、数据写入或对外协议，明确失败是否产生副作用以及如何回滚。
- 把 reviewer 很可能追问的边界直接写进方案，不留“到评审时再确认”。

## 六、证据与现状

- 对“已有”“已覆盖”“直接复用”“不需要改造”等结论查看真实代码、配置或权威文档。
- 技术方案阶段能确认的事实立即确认，不把代码查证任务写成待办。
- 发现 PRD、代码和口头信息冲突时，列出冲突并确认权威口径。
- 新概念首次出现时说明它是什么、来自哪里、由谁维护。
- 全文统一术语；相近词只保留一个确定说法。

## 七、表达与评审信息

- 删除无决策价值的章节、强调语、过程标记和“最小 / 建议 / 暂定”等无依据修饰。
- 复杂时序和分支使用图；时序图标出模块激活区间，并区分新增、改造和复用。
- 多字段协议、场景判定和任务拆分使用表格或带标题列表。
- 方案核心需要落地细节时给伪代码；已有实现细节与本次决策无关时只保留结论。
- 排期列出集成测试、验收、合并和发布节点，并暴露依赖与时间风险。

## 八、交付前反例扫描

用反对者视角逐句追问：

1. 删除这个对象或字段，方案是否仍能工作？
2. 为什么不能复用现有机制？
3. 消费者如何知道它存在？
4. 这段信息是否放在真正执行它的 Agent / Tool / 服务中？
5. 版本号对当前消费者有什么决策价值？
6. 失败、取消、超时或二次执行时会怎样？
7. 文档其他章节是否仍保留旧设计？

任何问题无法给出确定答案，都视为 Review 未通过。
